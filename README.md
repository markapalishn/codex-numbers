# Codex Numbers

Маленький нативный индикатор macOS: плавающая строка с расходом токенов,
нативное оформление Liquid Glass на macOS 26 и новее, автоматическое обновление каждые две секунды. Подписи на русском языке,
числа плавно меняются за 0,55 секунды. Пламя обновляется с целевой частотой
60 кадров/с; скорость движения не зависит от частоты кадров, пропущенные кадры
не накапливаются. В простое анимационный таймер отключается. При системной настройке уменьшения
движения анимация отключается.
Работает локально, без API-ключей, сетевых запросов и дополнительных библиотек.

## Установка

**[Пошаговая инструкция установки →](docs/INSTALL.md)**

В инструкции: подготовка Mac, загрузка проекта, установка с автозапуском,
обновление, удаление и решение частых проблем. Нужны macOS 26+ и актуальные
Xcode Command Line Tools с SDK 26+. Готовый установщик пока не публикуется.

После загрузки проекта выполните из его папки:

```sh
make install
```

## Использование

`make install` собирает приложение, устанавливает его в `~/Applications`,
сразу запускает и включает запуск при входе через пользовательский LaunchAgent.
Для сборки нужны инструменты командной строки Xcode со Swift.

Плашку можно перетащить за фон. Нажатие открывает аналитику, правый клик —
меню с выходом из приложения. В строке меню macOS показан процент использованного лимита. Положение сохраняется.
После завершения через меню приложение снова запустится при следующем входе.
`make uninstall` удаляет установленное приложение и автозапуск.
`make help` показывает остальные команды.

## Плашка

`Запрос: 105 000 токенов · Использовано: 12%`

На плашке есть векторное анимированное пламя и кольцо использованного лимита.
Пламя становится выше и активнее по мере роста числа токенов в текущем запросе:
от небольшого огня при 25 тысячах токенов до сильного при 300 тысячах
и максимального при миллионе. Между 800 тысячами и миллионом токенов
цвет плавно переходит в синий; от миллиона пламя полностью синее. После завершения или отмены запроса счётчик
на плашке плавно возвращается к нулю, а огонь гаснет. Плашка за 0,55 секунды
сворачивается до блока использования лимита; при новом запросе раскрывается.
Правый край остаётся на месте. Итог запроса остаётся в аналитике.
Это визуальная шкала токенов, а не стоимости. Подсветки при наведении нет.
Процент отражает расход общего лимита Codex по последнему снимку из журналов;
при нескольких окнах берётся наиболее израсходованное. Если свежих данных
после сброса нет, отображается «—». Меню приложения доступно также через процент в верхней строке macOS.

За запрос показывается сумма входных и выходных токенов всех обращений к модели.
Кэш уже входит во входные токены и повторно не прибавляется.
Число токенов не является ценой запроса или точной долей подписки.

При параллельной работе показывается один самый недавно обновлённый активный
пользовательский запрос. Расход других независимых запросов с ним не смешивается.
Дочерние обращения включаются в родительский запрос по `root_turn_id`;
если такой связи нет, они учитываются отдельно. Завершённая соседняя задача
не скрывает ещё работающий запрос. Незавершённые записи без событий более суток
считаются устаревшими для плашки, но остаются в аналитике.

## Аналитика

Нажмите на плашку, чтобы открыть аналитику; повторное нажатие закрывает её. Перетаскивание плашки
продолжает работать. В отдельной компактной панели доступны:

- периоды: сегодня, 7 дней, 30 дней, всё время;
- общее число токенов, число запросов и средний расход;
- график по часам/дням с точными значениями при наведении;
- вкладки «Проекты», «Модели» и последние 200 запросов;
- раскрытие проекта в список моделей с расходом и долей внутри проекта;
- фильтрация нажатием на вложенную модель или «Все запросы проекта»;
- названия запросов из первых слов исходного сообщения; текст при наведении
  (до 4 000 символов) и кнопка сброса фильтров.

История восстанавливается из журналов при запуске и обновляется автоматически.
Модель определяется для каждого обращения, поэтому смена модели внутри запроса
учитывается отдельно. Проекты различаются по полному рабочему пути (он виден
при наведении); разные рабочие копии могут отображаться отдельными строками.
Копии событий из разветвлённой истории не суммируются повторно.
Доступны только сохранившиеся локальные журналы; это аналитика токенов,
а не денежных списаний. Названия запросов берутся из пользовательских сообщений
в локальном журнале (`response_item` / `user_message`), а не генерируются моделью.
Первое сообщение используется как название запроса; дочерние обращения получают
название родительского. Служебные блоки с инструкциями не используются как названия.
Если текст отсутствует, показывается «Запрос без текста». Текст хранится только
в памяти приложения, не отправляется в сеть и не записывается в отдельную базу.

`make preview` сохраняет изображения основных состояний панели в папке `build`.
Для проверки компоновки стеклянный фон в этих изображениях заменён однотонным.

## Источник и ограничения

Основной источник — `token_usage_record` в `$CODEX_HOME/sessions`
(по умолчанию `~/.codex/sessions`). Для каждого уникального `response_id`
суммируются входные и выходные токены из `usage`, включая обращения сжатия
контекста. Записи группируются по `root_turn_id` (при его отсутствии — `turn_id`).
Кэш и reasoning повторно не прибавляются: они уже входят в соответствующие
входные и выходные счётчики. Модель берётся из контекста конкретного обращения,
проект дочерней работы — из родительского запроса.

Дубли одного ответа в нескольких файлах или ветках истории исключаются.
`token_count` не прибавляется к подробным записям: для одного и того же запроса
выбирается только один источник. Для старых запросов без `token_usage_record`
используется разница накопительных счётчиков; такие итоги помечены **≈**,
поскольку старый формат может не учитывать расход сжатия контекста.

Статус работы определяется по `task_started`, `task_complete` и `turn_aborted`.
Процент лимита берётся отдельно из `rate_limits` и не вычисляется из токенов.
Формат проверен на локальных журналах Codex 14 сентября 2026 года; это внутренний
формат, который может измениться. Облачные задачи без локального журнала
не отображаются. Текст запросов не сохраняется в отдельные файлы и никуда не отправляется.

Журналы читаются частями; незавершённые строки ожидают дописывания.
При запуске сначала загружаются 12 последних файлов, затем остальные.
`make test` проверяет сжатие, дубли, дочерние и параллельные запросы,
смену модели, границы запросов и дописывание файлов.
`make audit` сверяет потоковый подсчёт со всеми локальными подробными записями
и контрольными итогами `turn_token_usage`. Журналы остаются на вашем Mac;
команда выводит только число записей и расхождений. `make snapshot` показывает
текущий диагностический итог.
